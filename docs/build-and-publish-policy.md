# ビルド・確認・公開の方針

## 目的

執筆途中でも、読者に見せられる範囲のWeb版とPDF版を確認できるようにする。同時に、未完成の草稿や検証前の計算を誤って公開しない。

## 原稿と成果物

| 種類 | Gitで管理 | 目的 |
|---|---:|---|
| `.qmd`、図版、設定ファイル | はい | 原稿の正本 |
| HTML版 | 原則としていいえ | ブラウザで読む途中成果 |
| PDF版 | リリース時のみ | 印刷・オフライン確認用 |
| `_freeze/` | コードを実行した場合ははい | 計算結果の再現性を保つ |
| `_book/` などの一時出力 | いいえ | ローカル確認用の生成物 |

## ローカルでの作業

Quartoを導入した後、リポジトリ直下で実行する。

```bash
# 編集しながらWeb版を確認する（保存時に再描画）
quarto preview

# Web版とPDF版をまとめて生成する
quarto render

# 指定した形式だけを生成する
quarto render --to html
quarto render --to pdf
```

通常は `quarto preview` で、本文・数式・図・リンクを確認する。PDFは改ページ、図の大きさ、脚注、ページ番号、日本語フォントを確認する節目で生成する。

## 編集とレビュー

1. 章・節ごとに作業ブランチを作る。
2. `quarto preview` で確認し、HTML生成が通ることを確認する。
3. プルリクエストで原稿、図、生成プレビューをレビューする。
4. `main` へマージした内容を「公開候補」とする。
5. 節目の版をタグ付けし、PDFをリリース添付する。

## 公開の二段階

### 途中成果（Webプレビュー）

GitHub Actions が `main` の原稿をHTMLへビルドし、GitHub Pagesへデプロイする。QuartoはGitHub ActionsによるレンダリングとPages公開を公式にサポートしている。

ただし現在のリポジトリは非公開である。GitHub FreeではGitHub Pagesは公開リポジトリで利用でき、非公開リポジトリからのPagesはGitHub Pro以上などの契約が必要になる。さらに、非公開リポジトリ由来のPagesも通常はインターネットへ公開される。公開前に、リポジトリを公開するか、プランを利用するか、公開用リポジトリを分けるかを決める。

### 節目の成果（リリース）

章・部が読み通せる状態になったら、`v0.1.0` のようなタグを付ける。GitHub ActionsでPDFを生成してGitHub Releasesに添付し、Web版と対応する固定版を残す。

## 採用する自動化

Quartoプロジェクトの雛形を作る段階で、次を追加する。

- **Pull Request検証**：HTMLのビルドが成功するかを確認する。
- **手動公開**：最初はActions画面から明示的に実行してPagesへ公開する。
- **リリースビルド**：タグ作成時にPDFを生成する。

自動公開は、章の執筆と確認のリズムが固まってから `main` へのマージを契機に切り替えてもよい。
