# 編集・文章スタイルガイド

## 0. 確定原稿の優先

ユーザーが最終原稿として確定した文章は、本ガイドより優先する。確定原稿をリポジトリへ移す際は、誤字修正、表現改善、節の追加・削除を独自に行わない。媒体上必要な記法変換だけを機械的に適用する。

確定原稿は `docs/reference/` に正本として保存し、公開用原稿との一致は `python3 scripts/verify_approved_sources.py` で検証する。

## 1. 本書の文体

本文は、簡潔な学術説明文を基本とする。原則として「である」調で統一し、用語、数式、物理的意味の関係を体系的に記述する。

文体の基準は、次のような文章である。

> 物理学では、位置、速度、加速度、力、電場、磁場など、多くの物理量が、大きさと向きを併せもつベクトル（vector）として記述される。ベクトルの基本操作と線形性（linearity）を理解することは、物理現象を簡潔かつ体系的に記述・解析するための基礎となる。

- 会話的な呼びかけを基本の語り口にしない。
- 読者を引き込むための物語を本文の中心にしない。
- 過剰な比喩、煽り文句、編集意図を説明するメタ文章を用いない。
- 正確な専門語を使い、必要な箇所で平易な言葉による説明を添える。
- 日常的な例は、定義や論理を置き換えるためではなく、物理的意味を具体化するために用いる。

## 2. 用語と表記

- 専門語は最初の出現時に日本語を示し、必要なら英語を半角の丸括弧内に小文字で添える。例：ベクトル（vector）、線形性（linearity）。
- 専門語の強調には太字を用いる。かぎ括弧は引用または語として取り上げる場合に限る。
- 「概念」と「物理量」を区別する。位置、速度、力など、測定・計算の対象は原則として「物理量」と書く。
- 「同時に持つ」より「併せもつ」、「解き明かす」より「記述・解析する」など、意味が明確な表現を優先する。
- ベクトルは $\boldsymbol{A}$、大きさは $|\boldsymbol{A}|$、成分は $A_x,A_y$ と表す。
- 英字の物理量・変数は数式として記述し、本文中の装飾文字で代用しない。

## 3. 説明の基本構造

一つの概念は、原則として次の順に説明する。

1. **定義・対象**：何を扱う概念かを示す。
2. **計算・数式**：数学的な定義または計算規則を示す。
3. **物理的意味**：その式が現象の何を表すかを説明する。
4. **具体例**：中学数学または日常生活から想像できる例で確かめる。
5. **短問**：同じ操作を一度だけ自力で用いる。

基本操作を複数並べる節では、各項目の形式を `操作名 → 計算 → 物理的意味 → 具体例 → 短問` に揃える。

## 4. 文章

- 一段落には中心となる主張を一つ置く。
- 主語と述語の対応を明確にする。
- 抽象語を重ねず、どの物理量、物体、操作を指すか明記する。
- 同じ内容を、式、箇条書き、本文で不必要に繰り返さない。
- 「このように」「つまり」「したがって」は、論理関係が明確な場合に限って使う。
- 一文を長くしすぎず、条件と結論が複数ある場合は文を分ける。
- 「〜することができる」は、可能であれば「〜できる」または直接的な表現へ直す。

## 5. 表・箇条書き・callout

- 比較軸が揃う情報は表にする。
- 箇条書きは、計算、物理的意味、条件などの並列項目に使う。
- calloutは例題、短問、重要な注意に限って使う。
- calloutを二つ以上連続させない。
- 本文よりも枠や表が目立つ構成を避ける。

## 6. 数式

- インライン数式は `$ ... $`、表示数式は `$$ ... $$` を使う。
- Markdown内では `\[ ... \]` を使わない。
- ベクトルは原則として `\boldsymbol{A}`、ベクトルの大きさは `|\boldsymbol{A}|` と書く。
- 式の前に計算対象または定義を示し、式の後に物理的意味を記す。
- 等号変形が理解に必要なら途中式を示す。
- 数値例では単位を最後まで付け、数式内で `\mathrm{N}`、`\mathrm{m}` などと書く。

## 7. 問題と解答

- 一つの短問では、新しい判断または計算を一つだけ問う。
- 計算だけでなく、大きさ、向き、符号、単位を確認する。
- 解答には結果だけでなく、用いた計算規則を簡潔に記す。
- 本文で説明していない知識を、解答で突然使用しない。

## 8. 推敲

初稿を書いた後、次を確認する。

- 用語が物理学上正確であるか。
- 文体が「である」調で統一されているか。
- 会話的・物語的な導入が残っていないか。
- 数式と物理的意味が対応しているか。
- 例が定義の代用になっていないか。
- 編集方針や学習設計を説明する文が本文へ混入していないか。
